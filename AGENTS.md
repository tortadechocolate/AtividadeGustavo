# AGENTS.md — Regras do projeto

## 1. Objetivo

Desenvolver um site de portfólio pessoal moderno, criativo, minimalista e profissional, transmitindo a personalidade e a identidade visual do aluno.

O site deve ter aparência de um projeto desenvolvido por um designer, evitando completamente a estética de templates prontos ou sites genéricos.

## 2. Leitura obrigatória

Antes de começar qualquer desenvolvimento ou alteração, leia obrigatoriamente:

- `referencias.md`
- `identidade.md`
- `funcionalidades.md`

Esses arquivos são a principal fonte de orientação do projeto.

## 3. Tecnologias

- HTML5 para estrutura.
- CSS3 para estilização e animações.
- JavaScript puro para interações.
- Não utilizar frameworks como React, Vue ou Angular.
- Não utilizar bibliotecas desnecessárias.

## 4. Direção visual e design

- O design deve ser natural, elegante e visualmente equilibrado.
- Evite exageros visuais e elementos desnecessários.
- Não utilize gradientes em todos os elementos.
- Gradientes são permitidos somente no fundo principal e no header.
- Os demais elementos devem utilizar cores sólidas.
- Trabalhe bem os espaços vazios, alinhamentos, proporções e hierarquia visual.
- Utilize animações suaves e discretas.
- Evite sombras exageradas, bordas desnecessárias e efeitos chamativos.
- Não transforme o site em um template genérico de portfólio.
- Priorize uma identidade visual consistente em todas as seções.

## 5. Uso das referências

- Utilize somente os elementos descritos na seção "O que copiar" de cada referência.
- Não copie absolutamente nada que esteja listado em "O que NÃO copiar".
- Não invente elementos visuais das referências que não foram autorizados.
- Adapte os elementos selecionados à identidade visual do projeto.
- Não reproduza os sites integralmente.
- As referências servem como inspiração, não como modelos para clonagem.

## 6. Organização do código

- Utilize um único arquivo HTML principal.
- Utilize um único arquivo CSS.
- Utilize um único arquivo JavaScript.
- Organize o HTML com seções bem identificadas.
- Utilize nomes de classes claros e organizados.
- Evite código duplicado.
- Mantenha o código limpo e fácil de atualizar.

## 7. Responsividade

O site deve funcionar perfeitamente em:

- Celulares.
- Tablets.
- Notebooks.
- Monitores grandes.

Não permita textos cortados, elementos sobrepostos ou barras de rolagem horizontais indesejadas.

## 8. Animações

- Utilize animações suaves e naturais.
- Evite movimentos excessivos.
- Priorize transições fluidas.
- Não sacrifique o desempenho por efeitos visuais.
- Respeite a preferência `prefers-reduced-motion` do usuário.

## 9. Regras de desenvolvimento

- Desenvolva somente o que foi solicitado na etapa atual.
- Não crie seções futuras antecipadamente.
- Não altere a identidade visual sem necessidade.
- Não adicione funcionalidades que não estejam previstas.
- Antes de remover ou substituir algo existente, verifique seu impacto no projeto.

## 10. Após cada alteração

Ao terminar cada mudança:

1. Informe o que foi desenvolvido.
2. Explique brevemente as decisões tomadas.
3. Informe quais arquivos foram criados ou modificados.
4. Explique em duas linhas o resultado da alteração.

## 11. Regra principal

A qualidade visual é tão importante quanto o funcionamento.

O resultado deve parecer um portfólio autoral, com personalidade, consistência visual e acabamento profissional.
